# 数据库安装与初始化

本项目需要 **MySQL 8.x**（开发/验证用 8.4）。本文从零开始，覆盖安装、建库、建表、
导入演示数据、配置应用和常见问题。

> 本文不包含任何真实密码。所有密码都用 `__DB_PASSWORD__` 或 `change_me` 占位，
> 请在本机替换成自己的密码，并且不要提交到 Git。

## 1. 安装 MySQL 8.4

### 方式 A：Windows 安装包（推荐）

1. 打开 <https://dev.mysql.com/downloads/installer/>，下载 MySQL Installer。
2. 选择 **Server only** 或 **Custom**（至少包含 MySQL Server）。
3. 配置类型选 **Development Computer**，端口保持 **3306**。
4. 设置 root 密码并记住它；Windows 服务名通常是 **MySQL84**。
5. 安装完成后确认服务运行：

```bat
sc query MySQL84
```

也可以用 MySQL Workbench 连接 `127.0.0.1:3306` 验证。

### 方式 B：Docker（可选）

```bash
docker run --name train-mysql \
  -e MYSQL_ROOT_PASSWORD=change_me \
  -p 3306:3306 \
  -d mysql:8.4
```

等待容器初始化完成：

```bash
docker logs -f train-mysql
```

看到 `ready for connections` 后即可连接。

## 2. 创建数据库与应用账号

### 2.1 先改脚本里的密码

打开 `db/00_create_database.sql`，把两处 `__DB_PASSWORD__` 替换成你本机要用的密码，
例如 `TrainDev!2026`。这个密码后面要同时用于：

- 应用环境变量 `DB_PASSWORD`
- 功能测试 `functional_tests/.env` 里的 `DB_PASSWORD`

脚本会创建：

| 账号 | host | 用途 |
|------|------|------|
| `train_app` | `localhost` | 本机 socket / 部分客户端 |
| `train_app` | `127.0.0.1` | JDBC 走 TCP 时使用 |

> 已经建过库和账号的环境**不要重复执行** `00_create_database.sql`，
> 其中的 `ALTER USER` 会把现有密码改成脚本里的值。

### 2.2 执行建库脚本

用 root（或同等权限账号）执行：

```bash
mysql -u root -p < db/00_create_database.sql
```

如果使用 MySQL Workbench：打开脚本，确认已替换 `__DB_PASSWORD__`，然后执行。

### 2.3 建表与导入演示数据

```bash
mysql -u train_app -p train_ticket < db/01_schema.sql
mysql -u train_app -p train_ticket < db/02_seed.sql
```

`02_seed.sql` 会创建：

- 演示账号：`alice01 / Pass123`、`bob01 / Pass123`、`admin / admin123`
- 基础车次与未来 3 天的车票

这些是**自建演示系统的固定测试账号**，只用于本机演示和自动化测试。

### 2.4 验证

```sql
USE train_ticket;
SHOW TABLES;
SELECT COUNT(*) FROM users;
SELECT COUNT(*) FROM trains;
SELECT COUNT(*) FROM train_seats;
```

正常情况下 `users` 至少 3 条，`trains` 至少 10 条，`train_seats` 至少 60 条
（再执行压测种子后会多出 15 条 `train_id` 为 9001~9005 的座位）。

## 3. 配置应用连接

`src/main/resources/application.yml` 从环境变量读取数据库配置：

```yaml
spring:
  datasource:
    url: ${DB_URL:jdbc:mysql://127.0.0.1:3306/train_ticket?...}
    username: ${DB_USERNAME:train_app}
    password: ${DB_PASSWORD:}
```

### Windows cmd

```bat
set DB_USERNAME=train_app
set DB_PASSWORD=你的本机密码
mvn spring-boot:run
```

### PowerShell

```powershell
$env:DB_USERNAME = "train_app"
$env:DB_PASSWORD = "你的本机密码"
mvn spring-boot:run
```

### macOS / Linux

```bash
export DB_USERNAME=train_app
export DB_PASSWORD='你的本机密码'
mvn spring-boot:run
```

### IntelliJ IDEA

1. 打开 `TrainTicketApplication` 运行配置。
2. 在 **Environment variables** 里加：
   `DB_USERNAME=train_app;DB_PASSWORD=你的本机密码`
3. 启动后打开 <http://localhost:8080/login>。

> 项目里的 `.run/` 是本地 IDE 配置，已被 `.gitignore` 忽略；仓库不提供带密码的运行配置，
> 按上面的环境变量方式配置即可。

### 不想装 MySQL：H2 演示模式

```bash
mvn spring-boot:run -Dspring-boot.run.profiles=h2
```

或运行打包后的 jar：

```bash
java -jar target/train-ticket-0.0.1-SNAPSHOT.jar --spring.profiles.active=h2
```

H2 模式启动时自动建表并写入演示数据，进程退出即清空。
**只适合看页面/写脚本，不适合作为正式性能测试结果。**

## 4. 压测与功能测试数据

### 4.1 性能测试数据

```bash
mysql -u train_app -p train_ticket < perf/00_perf_seed.sql
```

每轮压测前复位：

```bash
mysql -u train_app -p train_ticket < perf/01_perf_reset.sql
```

会重置压测订单、库存和车票日期（`train_id` 9001~9005）。

### 4.2 功能测试数据

Selenium 套件启动时会自动执行 `functional_tests/00_test_seed.sql`，
重置 `FUNC01` 车次和三个座位。

功能测试连接配置：

```bat
rem 新建 functional_tests\.env，写入 DB_HOST / DB_USERNAME / DB_PASSWORD
```

`functional_tests/.env` 已被 `.gitignore` 忽略。也可以直接用环境变量：

```bat
set DB_USERNAME=train_app
set DB_PASSWORD=你的本机密码
```

## 5. 常见问题

| 现象 | 原因 / 处理 |
|------|-------------|
| `Access denied for user 'train_app'@'127.0.0.1'` | 没有创建 `'train_app'@'127.0.0.1'`，或密码不一致。重新检查 `00_create_database.sql` 与 `DB_PASSWORD` |
| `Access denied ... (using password: NO)` | 应用没读到 `DB_PASSWORD`。检查 IDEA 环境变量/终端 export |
| `Public Key Retrieval is not allowed` | JDBC URL 已有 `allowPublicKeyRetrieval=true`；如果你改了 `DB_URL`，保留该参数 |
| `Unknown database 'train_ticket'` | 先执行 `db/00_create_database.sql` |
| `Table 'train_ticket.users' doesn't exist` | 依次执行 `01_schema.sql`、`02_seed.sql` |
| `Schema-validation: missing table` | 表结构与实体不一致，重新执行 `01_schema.sql` |
| 端口 3306 被占用 | 改 MySQL 端口，并同步 `DB_URL` |
| 日期查询没有结果 | 压测前执行 `perf/01_perf_reset.sql`，把压测座位日期刷到明天 |
| 功能测试提示缺少 `DB_PASSWORD` | 新建 `functional_tests/.env` 并填写，或设置环境变量 |

### 修改已有账号密码

```sql
ALTER USER 'train_app'@'localhost' IDENTIFIED BY '新密码';
ALTER USER 'train_app'@'127.0.0.1' IDENTIFIED BY '新密码';
FLUSH PRIVILEGES;
```

### 清空压测数据

```bash
mysql -u train_app -p train_ticket < perf/02_perf_cleanup.sql
```

## 6. 安全说明

- 数据库密码只放在本机环境变量或 `functional_tests/.env`，不要写进 `application.yml`。
- `.env`、`.run/`、`perf/temp/` 和个人版《数据库操作.docx》都在 `.gitignore` 中。
- 本文和仓库中的 `Pass123` / `admin123` 是自建演示系统的固定测试账号，不是真实凭据。
- 如果要部署到共享环境，请换掉所有演示密码，并给数据库账号最小权限。
